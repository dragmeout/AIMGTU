# База знаний

## Файлы

```text
data/
  sources.csv                 # адреса, приоритеты и решения о включении
  preparation_config.json     # параметры сборки
  documents/
    raw/                      # оригиналы HTML и PDF
    manifest.json             # URL, время загрузки, размер и SHA-256
    clean/                    # очищенные документы в JSON и Markdown
    clean_documents.jsonl     # все включённые документы
  chunks/
    fixed.jsonl               # окна 180 слов, перекрытие 30
    semantic.jsonl            # разбиение по структуре, до 260 слов
    final.jsonl               # выбранный фиксированный вариант
    schema.json               # поля фрагмента
    example.json              # пример из final.jsonl
  evaluation/questions.jsonl  # вопросы и подтверждающие отрывки
  reports/                    # результаты проверки и сравнения
```

В `raw/` есть и исключённые документы. В RAG передаётся только `chunks/final.jsonl`.

## Воспроизведение

Из корня проекта, после установки `requirements-data.txt`:

```powershell
python scripts/prepare_data.py all
python -m unittest discover -s tests -v
python scripts/search_kb.py "Как восстановиться после отчисления?" --top-k 3
```

`all` заново извлекает текст, создаёт два разбиения, сравнивает поиск и проверяет результат. Сеть не используется. `search_kb.py` показывает найденные фрагменты и ссылки; ответы он не генерирует.

Для отдельного запуска доступны `build`, `compare` и `validate`.

## Обновление

```powershell
python scripts/prepare_data.py fetch
```

Команда скачивает только адреса из реестра. Внешние перенаправления блокируются. Результат записывается в `documents/manifest.json` и `reports/refresh_report.json`.

После загрузки нужно:

1. Посмотреть изменённые файлы и убедиться, что это нужные документы.
2. Проверить версию, даты, выбранные страницы и границы HTML-статьи.
3. Обновить строку в `sources.csv`. В `reviewed_raw_sha256` перенести проверенную сумму из манифеста. Само совпадение суммы не заменяет просмотр.
4. Выполнить `all` и тесты. Просмотреть исключения в `cleaning_report.json`.
5. Обновить вопросы, если правила изменились, и пересчитать сравнение.

Новый снимок с непроверенной суммой не индексируется. Если источник больше не нужен, поставьте `index_decision=exclude` и укажите причину. Файлы исключённого документа исчезнут из очищенного набора при сборке; оригинал остаётся в архиве.

Для нового формата PDF сначала задаются способ извлечения и проверенные физические страницы. Скан или сложная таблица не превращаются в текст автоматически. Дата проверки не подставляется вместо даты документа.

## Перед подключением к RAG

Сохраните `chunk_id` и ссылку на источник вместе с вектором. Учитывайте версию, дату обновления и ограничения использования. Размеры фрагментов здесь измерены словами. Перед вычислением эмбеддингов проверьте фактическое число токенов выбранной модели и разделите слишком длинные записи, сохранив связь с исходным фрагментом. Молча обрезать текст нельзя.

В текущем корпусе 70 документов по 16 темам. Дополнительные вопросы по 35 новым источникам: `evaluation/new_documents.jsonl`. Они не подменяют прежние 59 вопросов сравнения.
